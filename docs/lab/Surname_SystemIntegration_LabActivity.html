Part C · Registration integration

The browser sends the registration form to Laravel over HTTP. Laravel checks the form token and validates the name, student ID, course, email, and password. MySQL commits the account and linked profile together. The application then redirects to sign-in with confirmation.

During the demonstration, compare the saved user ID and the profile's user ID in MySQL. Verify that the password column contains a hash, then sign in, sign out, and sign back in to retrieve the saved profile. See Demo_Steps.md for the walkthrough and screenshots.

In the recorded Chrome run, fictional student QA-20261123-01 registered at 320 px. MySQL 8.4.13 confirmed one linked account and profile with a bcrypt hash. The saved ID and course appeared after signing in again.

Part D · Analysis

  1. How does the user interface communicate with the application server?

    The browser sends an HTTP request to a Laravel route. Laravel processes it and returns a rendered HTML page or a redirect. A trusted deployment should use HTTPS.

  2. What is the role of the database server?

    MySQL retains academic and account records and enforces relationships and uniqueness. Laravel retrieves these records when rendering each user's permitted views.

  3. What happens if the database server is unavailable?

    Requests that need the database can fail, so users may be unable to sign in, read records, or save changes. The application should show an error and confirm a save only after the database commits it.

  4. Why is authentication important?

    Authentication establishes who is making the request. Authorization then uses that identity to limit access, such as permitting teachers to grade only students in their assigned subjects.

  5. How does integration improve organizational performance?

    Registration, enrollment, and grades use linked records. Staff spend less time re-entering and reconciling information, and students can retrieve updates directly.

Section VIII · Reflection

  1. Integration and architecture

    Architecture defines the tiers and their responsibilities. Integration connects those tiers so a task can run across them.

  2. Scalability

    As student traffic and records grow, the system must remain responsive. Clear tier boundaries let operators improve constrained resources independently.

  3. Integration challenges

    Components can disagree about identifiers, data format, or permissions. Network failures and incompatible versions can also interrupt requests.

  4. Security and reliability

    A central application layer enforces permissions for database access. Transactions and database constraints keep linked records consistent when writes fail or users submit duplicates.

  5. What the project demonstrates

    Designing registration showed how a single form depends on routing, validation, authentication, and durable storage. Checking the profile after signing in again is an effective way to demonstrate persistence.

Section IX · Conclusion

The SIS brings a browser interface, Laravel application, and MySQL data store together to support registration and academic records. Each tier has a defined job, and the integration lets users follow one workflow from form submission through saved, protected data. Clear architecture makes that workflow easier to test and maintain.
